## Important Details
- Project: `/Users/muhammadadnan/Projects/pdf editor/pdf_editor_app` (Flutter 3.44.0; `dart_pdf_editor` 3.4.0 + vendored `vendor/pdf_document` engine). Do NOT modify the user's local backup.
- Local-only processing; no server/cloud/upload. No OCR/compression/AI/subscriptions.
- Engine primitives used (no engine changes): `PdfDocument.open(bytes)`, `PdfEditor(doc).appendPagesFrom(srcDoc)` then `save()`, `PdfDocument.extractPages(List<int> 0-based indices)` (deep-copies, order preserved, duplicates allowed), `PdfDocument.extractPageRange(start, end)` (0-based inclusive). Both split primitives carry page content (text/images/dimensions/orientation/annotations); document-level state (outlines, AcroForm field list, named destinations) is NOT carried — an accepted, reported engine limitation.
- Password-protected/corrupt/empty inputs rejected with `PdfToolException` user messages; encrypted extracts produce unencrypted output (engine behavior).
- Extract selection order = tap order; merge order = list order (drag-handle reorder via `ReorderableListView.onReorderItem`; `onReorder` is deprecated in Flutter 3.44).
- Merge destination = first source (incremental save); requires >= 2 PDFs (button disabled + service guard). Sources never modified.
- Split thumbnails: `PdfPageRenderer.renderImage` only when doc <= 40 pages at pixelRatio 0.4; larger docs show numbered tiles. Widget tests pass `showThumbnails: false`.
- Result screens: `MergeResultScreen` (editable filename default `Merged_Document.pdf`, Save via `DocumentIo.savePdf`, Share hidden on web via kIsWeb, Open in Docvera = push EditorScreen, Done = popUntil first). `SplitResultScreen` (per-part Save/Share/Open + Save all).
- Home header fixed: title `Flexible` with ellipsis (pre-existing 390px overflow exposed by new narrow test).
- Legacy dead code `lib/src/editor/tools.dart` removed earlier; engine chrome (measure/search) is real.
